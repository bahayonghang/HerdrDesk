# HD-036 实施与交付步骤

## 开始前

- [ ] HD-033/034/035 的证据对应同一候选 SHA；48 项原 AC 的各阶段贡献均可查。
- [ ] 批准本任务文档/状态收口范围；当前授权是否包含本地提交、任务归档、push、外部发布分别确认，已有授权不重复询问。
- [ ] 读取父任务的 task-map、acceptance-map 与本任务三件套。

## 执行顺序

1. [ ] 列出所有面向用户功能，按设计信息架构编写说明；实际按钮名称与实现一致。
2. [ ] 从真实测试结果生成/更新支持矩阵：Windows11 x64+Linux x64 首发，macOS/ARM64 等无对应证据不晋级。
3. [ ] 汇总 AC01–AC48 逐项证据，检查失败、未运行、旧 SHA、缺失平台及 synthetic 冒充 real；接收 HD-007/后续模块贡献，承担 AC39/40/47 最终责任。
4. [ ] 安排独立验收者按文档复现关键路径；只修复文档不一致或返回所属实现任务处理产品缺陷。
5. [ ] 同步源 planning/backlog、acceptance 与 tasks/HD 正文；不改 docs/plan 档案宣称现状。
6. [ ] 形成 release notes、许可证/NOTICE、依赖清单、hash、签名校验与更新回滚材料。
7. [ ] 完成文档链接/结构及父集成审查；确认最终 SHA 的干净锁定还原、完整 just ci/Actions、实际 required-check 失败阻断、依赖图/fake-port 业务用例发现，以及桌面/soak 证据。优先复用同 SHA 有效运行；缺失才执行，规则需变更时取得对应授权。
8. [ ] 在用户审阅具体候选后，只有外部授权齐全才执行发布；记录渠道返回结果，未发布则交候选。
9. [ ] 按实际授权本地提交/归档已验收任务；父任务不可因所有文件存在或工作树干净而标完成。

## 验证

现有命令：`python scripts/validate_repository.py`，以及实施后 HD-007 扩展的 `just ci`。文档链接/证据追溯可通过一次性审查脚本检查路径、48项覆盖和hash，不新增长期判断规则引擎。

未来 `docs/testing/release-checklist.md` 记录独立用户验收步骤；L3/L4 证据来自真正运行测试的任务，不能在这里补写“通过”。发布包签名/hash 在冻结后重新核验一次；无新变更、失败或未决风险不重复扩大测试。

## 失败处置与结束

文档与事实矛盾则改文案；产品 AC 未满足则阻断完整1.0发布并交原拥有任务修复。若维护者决定发布有限预览，单独说明缺失项，完整父目标继续未完成。

外部发布失败时保留可审阅的本地候选，不谎称上架成功；回滚不碰 daemon。结束报告需区分本地、hosted、桌面、soak、签名和渠道证据。
