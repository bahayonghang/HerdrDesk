# 05 · 协议与接口契约

## 1. 三种契约，不得混用

| 契约 | 提供方 | 传输 | 本项目行为 |
|---|---|---|---|
| herdr JSON RPC | 上游 | API socket / Windows named pipe 上的 NDJSON | 使用实际 schema；bridge 只做平台字节转发 |
| terminal session stdio | 上游 CLI | stdout 帧 + stdin 命令 + stderr 诊断 | 已核验 v0.8.2 格式；保留原始字节 |
| HerdDesk host/renderer 与 file helper | 本项目拟建 | 限定的结构化消息 | 单独版本号、授权检查；不能当作上游 API |

固定源码内嵌 schema 的 `protocol=20`、`schema_version=1` 只提供基线；实际运行先取 `herdr --version`、`herdr api schema --json` 并保存 hash，再用 RPC ping 核对 server。`api schema` 来自客户端 binary，不证明正在运行的 daemon 使用同一版本。远端也需独立采集，不能只检查 Windows 本机。[E03](../evidence/版本与证据索引.md#e03) [E07](../evidence/版本与证据索引.md#e07)

## 2. 上游终端 stdout：已经源码核验

下列是**合成示例，不是实际抓包**。字段来自 `src/client/mod.rs:850–1220`。`bytes` 是 Base64，不是名为 `data` 的 UTF-8 文本；`full` 是服务端编码器的重绘属性，不是新终端已完整重置所有模式的承诺。[E04](../evidence/版本与证据索引.md#e04) [E05](../evidence/版本与证据索引.md#e05)

```json
{"type":"terminal.frame","seq":1,"encoding":"ansi","width":120,"height":40,"full":true,"bytes":"G1sySg=="}
{"type":"terminal.closed","reason":"detached"}
```

`reason` 的值取决于运行路径，不建立未经验证的穷举枚举。桥在 UnexpectedEof 时可直接正常返回，没有 `terminal.closed`；退出码 0 不等于 pane 已关闭，stdout EOF 也不等于 daemon 已死亡。

## 3. 上游 stdin：已经源码核验

```json
{"type":"terminal.input","text":"你好"}
{"type":"terminal.input","bytes":"Aw=="}
{"type":"terminal.resize","cols":120,"rows":40,"cell_width_px":9,"cell_height_px":18}
{"type":"terminal.scroll","direction":"up","lines":3,"source":"wheel","column":5,"row":6,"modifiers":0}
{"type":"terminal.release"}
```

第二条的字节是 Ctrl+C，示例仅说明编码，探针不默认发送它。`text` 与 `bytes` 不能同时出现；`cols/rows` 必须为正 u16；scroll 的 `lines` 必须大于 0，方向 up/down，source 为 wheel/page_key。上游当前把缺少 text/bytes 的输入转成空字节；本项目 sender 应更严格，拒绝无有效负载的发送。

协议命令不提供逐条成功 ACK。stderr 中出现“input ignored”时应告警，不能等到 UI 看似有反应就标记所有命令成功；已发送但未获业务确认的危险文本标为“结果未知”，不自动重发。[E04](../evidence/版本与证据索引.md#e04)

## 4. RPC 能力映射

启动必需：`ping`、`session.snapshot`、`events.subscribe`。工作区、pane、agent 创建/关闭/重命名/排序从实际 schema 建立 allowlist，UI 只启用已验证的操作；不要用名称类似的方法猜参数。`workspace.*`、`agent.*` 不是可执行 CLI 字面命令。

```json
{"id":"hd-request-0001","method":"session.snapshot","params":{}}
```

事件订阅采用源码/文档支持的事件类型和过滤器；最低需覆盖 agent 状态、pane 生命周期、workspace/tab 变更与 layout 更新。精确 DTO 从导出的 schema 生成或手写并用真实 fixture 回归，不把动态文档里的新字段强加给 stable。发现未知字段时保存到扩展字典或忽略；未知 enum 保留 raw 值并降级显示，不反序列化崩溃。[E09](../evidence/版本与证据索引.md#e09) [E16](../evidence/版本与证据索引.md#e16)

由于没有通用 CLI RPC 通道，禁止在代码/文档写出虚构的 `herdr api call ...` 或 `herdr api events.subscribe`。`api snapshot` 只做 bootstrap/诊断，不能冒充实时订阅。[E03](../evidence/版本与证据索引.md#e03)

## 5. 自有 RPC bridge 规格（待实现）

建议接口：`herddesk-bridge rpc --socket-path <显式路径>`。这不是现有上游命令。Windows 版使用 `interprocess` 平台命名映射；Unix 版连接 Unix socket。stdin/stdout 保持 NDJSON 字节通道，所有 helper 诊断只走 stderr；helper 不在 stdout 插入欢迎消息或自有握手，`--version` 是独立命令。

构建 Windows x64、Linux x64/ARM64、macOS x64/ARM64 分别作为独立目标；远端不要求 Rust/.NET/Python 已安装，只部署经过授权确认和 hash 校验的匹配二进制。不存在“假设远端有 socat/nc/python 就算可用”的隐藏依赖。

`--socket-path` 必须来自已确认的设备/session 配置；Windows marker 文件不是普通可读取 API 通道。自动发现作为 G0 任务从上游路径解析、环境变量和实际 binary 行为验证；在此之前接受用户显式配置，不猜测 `%APPDATA%` 下某个路径即可连接。

## 6. 自有 host↔renderer 契约（草案）

只开放 `ready`、`input`、`resize`、`scroll`、`selection`、`frame-consumed`、`focus-changed`、`open-link-request`；不得开放 `runCommand`、`invokeAnyRpc`、`readFile` 等泛化代理。所有消息带当前 window/pane/epoch；native host 的选择与控制权为准，不能相信 JS 自报的任意 pane ID。

Host→renderer 的 payload 用 JSON 序列化而非拼接 `ExecuteScript`；终端字节走 Base64 后转换为 Uint8Array，不能插入 HTML。初期一次消息可聚合多个连续 frame，但每帧的 seq 与边界必须保留；renderer 回执只表示 parser 已消费到哪一帧，不代表上游已经执行输入。[E22](../evidence/版本与证据索引.md#e22) [E25](../evidence/版本与证据索引.md#e25)

## 7. 尺寸、限额、错误模型

建议初始预算：单条 NDJSON 上限 16MiB、decoded terminal frame 上限 8MiB、单可见 pane in-flight 上限 24MiB；这些是防御性客户端预算，不是上游声明的最大值。实际合法帧超预算时停止当前连接并提示限额，不截断 JSON、丢字节或悄悄丢掉 delta。

RPC 超时、SSH 认证错误、主机密钥改变、daemon 不可达、schema 不兼容、终端忙、桥 EOF、renderer 重启各有独立 domain 错误。消息保留技术详情供显式诊断导出，但默认日志不含终端正文、密码、密钥内容和上传文件字节。

接口草案见 `contracts/HerdDesk.Contracts.cs`；仅描述新项目 ports，未宣称已编译或已连接上游。
