# 10 · 测试、验收与 Before → Target

## 测试层级

| 层级 | 运行环境 | 测试对象 | 不能证明什么 |
|---|---|---|---|
| L0 静态包校验 | 当前Linux环境可运行 | 文档链接、JSON、任务依赖、合成协议fixture、脚本自测 | Windows GUI/真实herdr可用 |
| L1 Unit/Contract | Linux/Windows CI | Core、NDJSON、epoch、状态收敛、引用、限额 | 中文候选窗、真实SSH身份 |
| L2 Integration | 真实Windows 11 + herdr v0.8.2 | pipe、CLI桥、生命周期、控制/观察、资源回收 | 三类agent所有界面行为 |
| L3 E2E/人工 | Windows交互桌面 + Linux/macOS目标 | IME、agent TUI、通知、host key、文件、DPI | 长期运行不会退化 |
| L4 soak/fault | 受控测试资源 | 8小时负载、100次重连/切换、磁盘/权限/网络失败 | 未纳入矩阵的系统版本 |

PR必跑L1；涉及Windows生命周期与renderer的合并需L2；发布必须有L3/L4证据。Hosted Windows CI通常不等于可交互真机桌面，IME与屏幕阅读器必须人工或专用桌面runner验证。上游已有三平台CI不能替代本应用CI。[E08](../evidence/版本与证据索引.md#e08)

## 指标口径

统一参考机：至少8逻辑CPU、16GiB内存、SSD、Windows 11 x64，记录实际CPU/GPU/OS/WebView2/Display/DPI版本；本地30个pane状态、1个可见终端为基准负载，4个可见为扩展负载，远端额外记录RTT/丢包/带宽。所有数字是规划目标，尚未实测。

| 指标 | Before | Target / 验收目标 | 测量说明 |
|---|---|---|---|
| Core关键分支测试 | 未实现/未测 | changed-line覆盖≥85%，关键状态转换100%用例覆盖 | 不用全局覆盖率掩盖未测控制权 |
| 平均圈复杂度 | 未测 | 普通函数≤10；超过需评审拆分 | 复杂协议解析例外需记录，不宣称已达到 |
| 重复率 | 未测 | 新代码重复率<5%（排除生成DTO/fixture） | 同工具、同排除规则对比 |
| 依赖漏洞数 | 未扫描 | 已确认可利用Critical/High为0；例外须批准+到期 | 同时记录数据库日期和scanner失败 |
| 初次可操作窗口 | 未测 | 冷启动p95≤2.5s，网络不阻塞壳显示 | 不含首次安装runtime；另报首次setup |
| 本地输入→呈现 | 未测 | 低负载p95≤100ms，p99单独报告 | 不以xterm write callback充当实际呈现 |
| 远端输入→呈现 | 未测 | p95≤基础RTT+150ms（测试网络条件固定） | 服务器负载单独记录 |
| 全局搜索 | 未测 | 100条投影p95≤100ms | 不创建额外terminal进程 |
| 状态更新 | 未测 | 收到事件后UI更新p95≤500ms；断线校准另报 | dirty合并窗口包含在延迟内 |
| 空闲CPU | 未测 | 参考机总CPU占比≤1.5% | 测量App+自有bridge+WebView子进程 |
| 聚合工作集 | 未测 | 1可见pane≤500MiB，4可见≤900MiB | 包含App/WebView/自有bridge；herdr/agent另报 |
| 资源回收 | 未测 | 100次打开关闭后无持续增长；句柄容差≤5% | 等待GC/连接释放后比较基线 |
| 连接取消 | 未测 | 用户取消后自有桥≤3s退出 | 不终止daemon |
| 构建耗时 | 未测 | 缓存CI≤10min、干净CI≤20min | runner/缓存命中/原生产物分别记录 |

性能目标不是来自上游已测数据，而是本产品验收预算。无法达到时先保留正确性，调整并发/预算并记录ADR，不通过丢帧或吞输入美化数值。

## 首批必须跑的场景

Windows本地PowerShell pane→observe→control→输入中文→resize→release→GUI退出→外部重新连接。随后两个observer和两个controller测试独占；再在输入过程中模拟SSH断网、renderer重启、daemon退出、pane自然退出，确认所有原因被区分。真实输入试验只在可丢弃pane中进行，绝不在运行训练/生产操作的pane上自动发送键值。

Agent矩阵记录实际版本、shell、terminal renderer和协议基线；Claude Code/Codex/OpenCode只是首批验收对象，不预设已安装或所有新版本兼容。特别检查确认框、alternate screen、PageUp、鼠标、Shift+Enter、中文IME与Ctrl+C。与原始herdr客户端作行为对照，不靠“肉眼大致相似”通过。

文件矩阵包含0B、1KiB、50MiB、大文件、Unicode/空格/长名、同名冲突、权限拒绝、symlink、网络断开、磁盘不足；成功标记必须在hash与原子rename完成后给出。

## 发布标准与证据归档

完整48项AC在 `planning/acceptance.json`。每项至少记录环境版本、命令/步骤、预期、实际、证据路径、人工验收者、相关commit及缺陷编号。一个AC可能覆盖多个平台，某个平台未测不允许借别的平台结果标passed。

`fixtures/` 中数据全部为synthetic；`scripts/probe_herdr.py selftest` 只验证探针自身，不证明herdr契约运行可用。`scripts/probe_herdr.py observe ...` 只检查收到的桥数据形态，不证明TUI像素、输入法或滚动完整。
