# 08 · 安全与威胁模型

## 1. 信任边界

HerdDesk 运行在普通交互用户权限下。可信代码只有签名/已校验的应用与依赖；**terminal 输出、远端文件名、agent 的标题/提示、SSH 服务端响应都属于不可信数据**。能在 pane 输出文字的远端程序不能因此获得 Windows 文件访问、任意命令执行或自动点击批准权限。

浏览器 renderer 的 host 消息是特权边界。Microsoft 明确要求核验 WebView2 origin、验证消息、避免泛化代理并最小权限运行；本设计据此限制能力。[E22](../evidence/版本与证据索引.md#e22)

| 资产 | 威胁 | 控制 | 验收 |
|---|---|---|---|
| 本地命令执行权 | pane 内容伪造 JS/host 消息 | 本地固定 origin；字节只进 xterm；无 generic exec proxy | 恶意 ANSI/HTML/消息不能创建进程 |
| 用户输入 | 旧 epoch 或 pane ID 把输入送错机 | Host 校验 current session/epoch/控制权 | 快速切换与通知跳转竞态 100 次零串写 |
| SSH 凭据 | 日志、CLI 参数、错误导出泄漏 | ssh-agent/凭据引用；禁止密码 argv；输出脱敏 | 导出无私钥/密码/终端正文 |
| 主机身份 | MITM、known_hosts 被覆盖 | 已核验 fingerprint；变更硬失败 | host-key change 不自动接受 |
| 上传内容 | 路径遍历、symlink、TOCTOU | 独占临时文件、规范化、权限检查、原子 rename | 攻击性文件名/并发冲突测试 |
| agent 会话 | UI退出误杀，重连乱序输入 | 进程 ownership allowlist；不重放 input | 关 GUI 后 pane 继续；网断不提交旧命令 |
| 更新链 | 替换 bridge/renderer 依赖 | 签名+hash+SBOM+最小权限发布 | 篡改产物拒绝启动/安装 |
| 可用性 | 超长行、高速输出、无限事件 | 行/帧/队列预算、限流、超时、取消 | 压测内存有界；恢复输入可用 |

## 2. 默认策略

App 不以管理员身份运行，不替用户修改系统防火墙、SSH 服务、agent policy 或 daemon 的开放接口。后台不会默认添加危险 agent 参数；熟练用户的免审批设置要 per-agent/per-device 可见，并保留撤销入口。该策略是本产品的安全选择，不是声称上游默认行为构成已证实漏洞。

`--takeover` 仅由明确确认产生，不绑定到“打开 pane”。创建/关闭/发送命令在 UI 显示目标设备/session；重连时禁用所有可能产生副作用的按钮，直到状态重新收敛。通知深链接只可定位已有实体，不能携带待执行命令。

## 3. WebView2 与终端安全

JS 与字体等资源随安装包分发，禁止 CDN；不打包未经授权字体。固定本地资源 origin，限制 NavigationStarting/NewWindow/下载/权限请求；需要 JS 与 web messages 的 terminal 区不把这两项简单全部关闭，而是采用严格 schema allowlist。默认关闭 host objects、开发工具和任意 dialogs；调试模式与发布模式分开。

使用 `PostWebMessageAsJson`，不要将终端 bytes、文件名或标题拼入执行脚本。只在来源/epoch 验证通过后接受 renderer 消息；`IsTrusted` 类来源标签只能作为辅助手段，不能替代 host 权限判断。输入、窗口尺寸、链接请求均有长度和范围限制。xterm 输出不插入 innerHTML；链接只允许经用户手势触发的 http/https，其他 scheme 由明确策略处理。[E22](../evidence/版本与证据索引.md#e22) [E24](../evidence/版本与证据索引.md#e24)

默认拒绝 OSC 52 读剪贴板；对于写剪贴板或打开文件，不让屏幕输出直接触发敏感动作。输出日志/录屏是单独 opt-in 功能，默认不记录。控制台文本可能包含代码、token、训练数据路径甚至凭据，不能认为“只是日志”就安全。

## 4. Named pipe 与子进程

只连接本地、预期用户/session 的 endpoint；不允许把用户输入自动解释成远程 SMB named pipe。验证实际 API 管道 DACL、server process owner 和权限失败表现。上游 private listener 有显式 DACL 分支，但这不能证明每个 API endpoint 都使用同一保护。端点 ACL 不通过时，不以 administrator 运行应用来掩盖问题。[E06](../evidence/版本与证据索引.md#e06)

所有子进程使用固定、校验过的 executable path，不从当前工作目录搜索同名 herdr/ssh。App 只终止自己的桥子进程；对于 daemon 的首次启动，不把其纳入会随 UI 退出杀死的 job。若使用 shell/远端命令字符串，建立统一引用函数并 fuzz 测试；不允许不同 ViewModel 各写一份拼接。

## 5. 供应链与许可

对最终 NuGet/npm/Cargo/打包工具依赖执行漏洞和 license 扫描，记录 scanner、数据库日期、版本、direct/transitive 分类；扫描失败不能写“0 CVE”。对 reachability 做人工复核，有例外记录和到期日；不存在“公开仓库所以全都开源可复制”的默认规则。

herdr 在 Cargo 声明 Apache-2.0，但最终分发仍需检查 LICENSE/NOTICE 与 vendor 依赖。herdrm 根目录未见 LICENSE，本资料不复制其代码、图标、字体、截图或完整文档；独立实现不自动构成法律意义上的 clean-room 认证。若将其源代码用于衍生实现，先取得合适授权和必要审查。[E01](../evidence/版本与证据索引.md#e01) [E13](../evidence/版本与证据索引.md#e13) [E26](../evidence/版本与证据索引.md#e26)

## 6. 安全发布门禁

发布阻塞项：可复现的错设备输入、未经确认的 takeover/自动批准、任意 JS→process 通道、host-key 变更未阻止、应用退出导致 daemon/agent 死亡、无界内存增长、已确认可利用的严重依赖漏洞、未解决的分发授权。

安全事件回滚时先停用受影响 UI 功能/撤回应用版本，不主动终止用户训练或 agent。诊断导出由用户勾选，默认只包含版本、操作分类、相关 ID 的脱敏映射、错误类别、时延与限额指标。
