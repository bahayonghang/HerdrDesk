# 11 · 工程化、发布与运维

## 构建与依赖

创建可复现的工具链清单：.NET SDK精确版本、Windows App SDK NuGet精确包版本、WebView2 SDK/runtime检测策略、npm锁文件、Cargo.lock、Rust工具链。G0先验证稳定产品版本与包版本对应关系，不凭记忆填写不存在的NuGet版本。依赖小步升级，每次记录schema与TUI回归影响；Windows App SDK更新不和herdr更新强绑定。[E19](../evidence/版本与证据索引.md#e19) [E20](../evidence/版本与证据索引.md#e20) [E21](../evidence/版本与证据索引.md#e21)

C#启用nullable、analyzers和警告评审；Core单元测试用fake transport；Rust bridge运行fmt/clippy/test与多平台构建；JS跑typecheck/lint/contract/renderer测试。质量工具必须在目标工具链实测命令，不能把计划中的命令输出当已完成的CI结果。

建议流水线：lint/typecheck→unit/contract→Windows integration→打包→签名验证→发布草稿。发布凭据使用最小权限和受保护环境；锁定Action revision，artifact和日志保留明确期限。长时间soak可定期或release候选执行，但没有通过不能默默转stable。

## 安装与更新

正式优先签名MSIX，配套明确的更新通道；App Installer/Store/企业分发择一作为主机制，WinGet仅作为分发/安装入口之一，不能把“上架WinGet”当作应用内更新系统已完成。预览与稳定包身份/配置要防止相互覆盖。

代码签名降低来源不明风险，但不能保证SmartScreen完全不提示。记录Publisher与证书续期流程；不在源码内嵌私钥。WebView2使用Evergreen时提供缺失检测和受控安装引导；离线环境评估Fixed Version策略并承担补丁发布责任，安装包体积单独计量。

应用更新与herdr daemon更新解耦。升级应用只重建自有连接；默认不下载/替换用户herdr、不停止agent、不抢占已有控制者。自有bridge/filehelper要有版本兼容检查，不能在活跃传输中替换；保留上一可用版本，原子切换后再清理。

## 配置和数据迁移

配置采用版本化JSON、临时文件原子替换与迁移前备份。路径建议使用Windows应用数据API而非硬编码用户目录；设置、cache、logs分目录。配置只存身份引用，不存私钥/密码。设备/用户ID稳定，名字可改；删除设备默认仅删除客户端配置，不清空远端任务或文件。

回滚前确认配置向后兼容；不可逆迁移要采用导入新文件而非原地破坏。卸载是否清除配置/缓存由用户选项决定，不删除herdr的数据目录和远端私有文件。

## 可观测性

结构化事件至少包含component、operation、device/session脱敏ID、epoch、duration、outcome、error category、queue bytes与版本。默认不记录ANSI正文、用户输入、剪贴板和文件内容。提供用户可预览的诊断导出；导出前隐藏远端地址、用户名与绝对路径，支持用户明确保留必要排障信息。

监控重点：RPC超时/取消、订阅重建次数、投影校准时延、terminal EOF原因、控制申请失败、输入拒绝、帧队列峰值、renderer reset、传输失败与临时文件清理。不能把网络问题一律归为“named pipe超时”。

## 支持与发布说明

每次release列出支持Windows/远端OS/agent/renderers的实际组合，保留known limitations。区分“源码上有实现”“测试通过”“用户报告”三个证据等级；stable与preview的问题分开。版本号、能力门禁与FAQ引用同一份compatibility manifest，避免README和真实行为脱节。
