# 02 · 产品定义与名称

## 产品决定

**应用名称：HerdDesk。中文工作名：牧台。** 定位为“Windows 原生 herdr 工作台”。使用独立品牌与图标；关于页明确“Independent Windows client for herdr; not an official herdr/herdrm release”。名称为本方案设计建议，未完成商标、域名、包名和发行商名称核验，不能宣称独占可用。

推荐仓库 slug `herddesk`，C# namespace `HerdDesk`，可执行文件 `HerdDesk.exe`，自有桥程序 `herddesk-bridge`。发布 Publisher/Package Identity 在 G0 确认后冻结，未提前编造 GUID、证书身份或已注册域名。协议 deep link 的工作名 `herddesk:` 也须通过安装冲突检查。

产品核心不是再包一层完整 herdr TUI，而是：用户在一个 Windows 窗口查看多设备、多命名 session 的工作区与 agent，点开目标 pane 后看到可操作的真实终端视图，并能明确区分观察、控制、失联和被接管。herdr 仍拥有工作进程，HerdDesk 只拥有连接。herdrm 已采用分离服务层和 UI 的产品结构，可作为行为对照而非默认代码来源。[E09](../evidence/版本与证据索引.md#e09) [E14](../evidence/版本与证据索引.md#e14)

## 场景与边界

首要场景为 Windows 开发机管理本机任务，同时通过 SSH 查看 Linux 训练机/实验机；保留普通 shell pane，不仅支持命名 agent。用户不需要为了查看一条任务而理解 multiplexer 的完整键位表。研究数据、代码和模型文件默认留在设备上；上传/粘贴始终有明确目标设备。

**正式支持面**：处于厂商支持范围内、经项目 CI 和真机测试的 Windows 11 x64；远端 Linux x64 首发，macOS 和 ARM64 由独立测试矩阵晋级。Windows 10、Windows ARM64、WSL、Windows 远端宿主均不得仅凭“底层理论支持”自动进入支持承诺。Windows 10/ESU/LTSC 的具体 SKU 与依赖兼容性另行验证，原报告的“1809+ 全支持”不作为本产品指标。

**不进入 v1**：替代 herdr daemon、原始 PTY 录制/回放保证、默认自动批准 agent、高危命令无确认执行、跨设备实时硬件控制、Windows 被控宿主、云账号同步、插件市场、内建模型计费、像素复刻 macOS、保证所有 Kitty/Sixel 图像协议。对 PLC 或工业设备，本产品只是操作工具，不是安全联锁/实时控制器。

## 信息架构与界面规范

主窗口为四个固定区域：窄设备/session 区；workspace 与 pane 树；中央 terminal；可收起的详情/文件区域。顶部显示设备名、session、连接状态和控制权；危险操作放入有文本说明的菜单，不依赖只有颜色的图标。

Agent 业务状态 `working/blocked/done/idle/unknown` 与连接状态、未读状态、控制权各自建模。`done` 不自动等于成功，`blocked` 不自动等于权限请求；原始状态不认识时显示“未知”，不擅自映射为 idle。UI 用中文“工作区”表示 workspace，用“会话”表示 named session；内部类型保留英文。

| 操作 | 建议快捷键 | 保护规则 |
|---|---|---|
| 全局搜索 | Ctrl+K | 组合输入期间不拦截 IME |
| 新 agent / terminal / workspace | Ctrl+N / Ctrl+T / Ctrl+Shift+N | target 设备/session 始终可见 |
| 复制 / 粘贴 | Ctrl+Shift+C / Ctrl+Shift+V | Ctrl+C 在终端默认保留 SIGINT 语义 |
| 切换观察/控制 | 工具栏明确按钮 | 不把聚焦自动等同 takeover |
| 换行 vs 提交 | 按 agent 经过测试的键序列 | Shift+Enter 不做跨 agent 统一保证 |

Mica 用于外壳，不要求 terminal 背景透明；深浅色/高对比度采用语义色资源。终端颜色不在传输层重写，避免破坏 ANSI 语义；主题属于 renderer 展示策略。屏幕阅读器、键盘全访问、字体缩放、100/150/200% DPI 和多显示器是功能，不是最后美化。

## 全量对等的剩余范围

本计划中的1.0是**核心功能对等版本**，不宣称覆盖herdrm所有认证方式、standalone终端和图形协议。完整产品路线还应保留以下1.x扩展；它们不计入36项基线任务的57–99人日预算，确定优先级后再拆解任务和AC。

| 后续工作包 | 新增范围 | 前置条件 | 单独验收/回滚 | 额外估算人日 |
|---|---|---|---|---|
| EP-01 | App自有本地/远端standalone shell | 与herdr终端类型和所有权严格区分 | 关闭提示、断线恢复、进程回收；失败可禁用此类tab | 5–10 |
| EP-02 | SSH密码/MFA与Tailscale专门交互 | 安全凭据provider、明确交互桌面流程 | 不泄漏密码、不无限提示；可回退key/agent | 5–12 |
| EP-03 | 更完整的工作区/tab排序与agent启动配置 | 实际schema支持、创建操作幂等保护 | 多客户端同时修改不丢排序；失败回权威状态 | 3–6 |
| EP-04 | 原生renderer正式替换 | 与WebView版相同48项相关AC通过 | 可按设备/全局切回WebView，不改Core | 8–20 |
| EP-05 | Windows ARM64、更多远端平台与WSL | 工具链/二进制/交互硬件齐备 | 每组合独立支持表，失败保持experimental | 4–10 |
| EP-06 | 图形协议、增强键盘及更完整VT特性 | 上游桥能力与消息传递验证/必要时贡献上游 | 文本路径不退化；不支持的协议明确降级 | 6–20+ |
| EP-07 | 标准SFTP provider与扩展认证一致性 | 库许可、安全与OpenSSH profile映射验证 | 既有文件面回归全过；失败切回file helper | 4–10 |

这些范围不能用“先做一个窗口”隐含承诺。发布文案与支持矩阵只列实际通过的功能；原生纯度、图像协议和多认证提供方均可以扩大维护责任。
